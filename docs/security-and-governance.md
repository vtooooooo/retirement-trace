# Security and governance

Cloudflare Pages serves the React application and proxies same-origin HTTPS API requests to Render. A server-only edge credential gates Render's application endpoints. The application restricts CORS to configured origins and requires an exact allowlisted Origin for state changes, including login and logout. Authenticated responses are uncached and security headers apply to the app and API.

Render stores separate server-side account records as salted scrypt hashes. Signing in issues an opaque session cookie with Secure, HttpOnly, SameSite=Lax and a host-only `__Host-` prefix in hosted mode. PostgreSQL stores only the session token digest, expiry and account binding. Sessions expire after eight hours. Logout deletes the session, and account credential changes invalidate prior sessions. PostgreSQL also stores rate-limit counters, shared by all running instances. Login limits are 10 attempts per account and 30 per source IP in five minutes, with 180 authenticated requests per account per minute.

Analysts triage and investigate and may submit review requests. Senior reviewers adjudicate independently and can return a case for further work. Benefits operators resolve reviewed cases. Auditors can search, review and export evidence. Role and tenant scope are enforced on every API request. Decisions require rationale, a current revision and an idempotency key. Events persist account, actor, timestamp, state, version and action reference.

Attachments are internal reference metadata. Synthetic operation excludes file upload, participant contact, disbursement, and external identity verification. The hosted demo has no enterprise SSO, account provisioning UI, evidence redaction, retention administration, or immutable external audit storage. Use synthetic data and credentials assigned by the operator only.
